# NetMap Planner

Кроссплатформенный планировщик адресного пространства и карт сети:
калькулятор подсетей IPv4/IPv6 и проекты с холстом и списком устройств.

Цель платформ: **Windows** (сейчас), **Linux AppImage** и **Android APK** (следующие этапы) из
одного кодовой базы.

## Что уже работает

- **Калькулятор подсетей**
  - IPv4 и IPv6 с полной поддержкой граничных случаев: `/0`, `/31` (RFC 3021), `/32`,
    IPv6 без broadcast, первый адрес как subnet-router anycast.
  - Ввод `10.0.0.1/24`, `10.0.0.1 255.255.255.0`, `2001:db8::1/64`, голый адрес.
  - Сеть, broadcast, маска, wildcard, первый/последний хост, количество адресов и хостов,
    биты хоста, обратная зона DNS.
  - Определение класса IPv4 (A–E) и классовой маски, приватности и публичности по реестру
    IANA (с RFC-ссылками): private, CGNAT, loopback, link-local, multicast, документация,
    ULA, NAT64, 6to4, Teredo и т.д.
  - Визуальный редактор бит: клик по биту меняет адрес, сетевые/хостовые биты подсвечены.
  - Разбиение на подсети по новому префиксу — постранично, включая IPv6 (`/0` → `/64`
    без перебора адресов).
  - Режим «На N подсетей»: N округляется вверх до степени двойки, префикс подбирается
    автоматически (`/24` и N=5 → `/27`), с подсказкой об округлении и обрезке по максимуму.
  - Список адресов блока с ролями (сеть, broadcast, anycast, host route, point-to-point)
    и переходом к хостам конкретной подсети.
  - История запросов: поиск, избранное, удаление, хранение между запусками.
  - Светлая и тёмная темы; адаптивная раскладка под узкие окна и будущий мобильный экран.

- **Каркас приложения**: Electron-оболочка с изолированным preload-мостом и файловым
  хранилищем (JSON в `userData/storage`), Vite + TypeScript + Preact, Vitest.

- **Проекты (M2)**
  - Список проектов: создание, переименование, дублирование, удаление, экспорт JSON,
    импорт JSON с мягкой миграцией схемы.
  - Режим списка: таблица устройств с типом, слоем L1/L2/L3, ОС, ролью, группой,
    портами и адресами; поиск по имени, IP, MAC, роли и ОС, фильтр по группам.
  - Устройство может входить в несколько групп: набор чипов в редакторе, фильтр и
    проверка учитывают все группы.
  - Мосты как в Linux: отметьте порты (ens34, ens35, ens36) и объедините их в br0 —
    мост получает собственный IP, участники исключаются из выбора портов для связей,
    состав можно менять, проверка предупредит об IP на порту-участнике и связи через него.
  - Редактор устройства: атрибуты, теги, заметки, порты (среда, скорость, режим, VLAN, MAC)
    и адреса IPv4/IPv6 с выбором роли. Адреса проверяются на формат и дубликаты прямо в форме,
    рядом с адресом показывается его подсеть, а адрес сети/broadcast помечается предупреждением.
  - План адресов: блоки CIDR, занятость и прогресс, свободные адреса, «следующий свободный»,
    выдача свободного адреса из плана одним нажатием, проверка пересечения блоков,
    редактирование блока (CIDR, название, владелец) без удаления и повторного создания.
  - Проверка проекта: дубликаты IP и MAC, совпадающие имена, битые связи, адреса вне плана,
    назначение адреса сети и широковещательного адреса. Общий VIP-адрес (VRRP) дубликатом
    не считается.
  - Автосохранение каждого проекта в отдельный JSON, запоминание раздела и открытого проекта.
  - CSV-экспорт устройств.

- **Холст (M3)**
  - Отрисовка устройств: узлы с типом, слоем, ОС, ролью, IP, привязкой к координатам.
  - Связи: медиа (медь, оптика, Wi-Fi, WAN, виртуальная), цвета по типу, изломы, подписи.
  - Связи привязаны к портам: точка крепления рисуется на границе узла, подпись порта видна
    при приближении, панель выбранной связи позволяет сменить порты на обоих концах, медиа и
    подпись. Параллельные связи между одной парой устройств разводятся со смещением, а клик
    по пучку перебирает их по кругу («связь 2 из 3») — каждую можно настроить или удалить.
  - Подсказка при наведении: все порты устройства со средой и адресами (DHCP/SLAAC
    подписываются явно, а не как обычный адрес).
  - Слои: структура (устройства + связи) и заметки/рисунки, порядок отрисовки, видимость,
    блокировка, «поверх рисунков» (pinnedTop), легенда типов связей.
  - Инструменты: выбор, связь (drag from device to device), рамка, эллипс, заметка, текст,
    стрелка, линия. Палитра цветов применяется к новым рисункам и к выбранному.
  - Управление сценой: панорама (drag), зум (колесо), привязка (snap), сетка, «вписать всё».
    Новые устройства автоматически встают в свободное место без наложения.
  - Выделение: множественный (Shift), удаление (Delete/Backspace) устройств, связей и рисунков,
    двойной клик — редактор.
  - Модальные окна: редактирование текста заметок, создание/редактирование текстовых аннотаций.
  - Undo/Redo (Ctrl+Z / Ctrl+Y), история до 80 шагов.
  - Адаптивный холст: минимальная высота, сворачивание инструментов на мобильных.
  - Статус-бар: счётчик устройств, связей, выделенных, координаты курсора, подсказки.

- **Экспорт и поиск (M4)**
  - Экспорт холста в PNG: кнопка на панели инструментов и Ctrl+S.
  - Быстрый поиск (Ctrl+F, также Ctrl+K): устройства по имени, IP, MAC, ОС, роли, вендору, модели,
    местоположению, тегам; связи по подписи, медиа и именам конечных устройств.
    Клик по результату выделяет устройство или оба конца связи.
  - Хоткеи: Ctrl+F (или Ctrl+K) — поиск, Ctrl+S — экспорт PNG, Ctrl+Z/Ctrl+Y — undo/redo,
    Delete/Backspace — удалить выделенное, Escape — сброс инструмента.
    Инструменты: V — выбор, L — связь, R — рамка, O — эллипс, T — текст, N — заметка,
    A — стрелка, I — линия. Комбинации распознаются по `event.code`, поэтому работают
    и в русской раскладке.

Сейчас закрыты этапы **M1–M4** и заготовки M5: Android-проект (Capacitor) собирается в APK,
добавлены конфиг Linux AppImage и CI для трёх платформ.

## Запуск

Нужны **Node.js 22+** и npm. Для Android-сборки — **JDK 21** и **Android SDK**
(platform 36, build-tools 36.0.0). Для Windows/Linux-сборки дополнительных
инструментов не нужно: Electron скачивается через npm.

```powershell
git clone https://github.com/Feokor/NetMap-Planner.git
cd NetMap-Planner

# поставить зависимости ровно из package-lock.json (один раз)
npm ci

# веб-версия для разработки
npm run dev            # http://localhost:5173

# приложение в Electron (Vite + окно с hot reload)
npm run electron:dev

# тесты IP-ядра и истории
npm test

# проверка типов и сборка веб-бандла
npm run build

# окно Electron с production-сборкой
npm run build; npx electron .

# портативный exe (один файл, кэширующая распаковка) + zip-архив
npm run dist:portable   # -> release/NetMapPlanner-<версия>-portable.exe и *-win.zip

# Linux AppImage (собирается на Linux или в CI)
npm run dist:linux      # -> release/NetMapPlanner-<версия>-x86_64.AppImage

# Android: синхронизировать веб-сборку и собрать debug APK
npm run android:sync
npm run android:apk     # -> android/app/build/outputs/apk/debug/app-debug.apk

# перерисовать иконку (build/, public/, Android mipmap) — без внешних зависимостей
npm run icons
```

## Tauri (экспериментальная оболочка)

Тот же веб-бандл можно запускать не только в Electron, но и в Tauri 2 — окно на WebView2,
размер сборки в разы меньше. Android при этом остаётся на Capacitor, Electron-сборка тоже
никуда не делась.

Что нужно: **Rust 1.77+** и **MSVC C++ Build Tools** (Visual Studio Installer → рабочая
нагрузка «Разработка классических приложений на C++»). WebView2 уже есть в Windows 10/11.

```powershell
# окно Tauri с hot reload
npm run tauri:dev

# одиночный exe без установщика
npm run tauri:build      # -> release/NetMapPlanner-<версия>-tauri.exe

# то же на Windows, если Visual Studio не создала vcvars64.bat:
npm run tauri:build:win

# NSIS-установщик
npm run tauri:installer  # -> src-tauri/target/release/bundle/nsis
```

Tauri хранит данные в `%APPDATA%\ru.vibe.netmap\storage`. При первом запуске проекты из
папки Electron-версии (`%APPDATA%\vibe-netmap\storage`) копируются автоматически, так что
переход не теряет карты.

В git попадают только исходники, конфиги, тесты, CI и скрипты сборки. Не попадают
`node_modules/`, локальный тулчейн `.tools/`, временные `.tmp/`, собранные `dist/` и
`release/`, Android-сборка (`android/**/build`, `.gradle`, `local.properties`,
сгенерированные assets), ключи подписи (`.jks`, `.keystore`, `keystore.properties`)
и файлы `.env*`. Поэтому после клонирования не нужно ничего чистить — достаточно `npm ci`.

Портативный exe распаковывает приложение **один раз** в
`%LOCALAPPDATA%\VibeNetmap\app-<версия>` и при повторных запусках сразу стартует — это
заметно быстрее штатного self-extracting launcher'а Electron, который распаковывал ~250 МБ
при каждом запуске. Замер на машине разработки: холодный старт (с распаковкой) — **2,7–3,1 с**,
тёплый — **0,4–0,45 с**. Zip-архив даёт такой же быстрый старт после однократной распаковки.
Старые версии из этого каталога удаляются автоматически.

Каталоги `%APPDATA%\vibe-netmap` (проекты) и `%LOCALAPPDATA%\VibeNetmap` (кэш распаковки)
сохранены с прежними именами после переименования в NetMap Planner — чтобы не потерять
пользовательские данные и не распаковывать 150 МБ заново.

Распаковка идёт через временный каталог `app-<версия>.tmp-<pid>` и префикс длинных путей
Windows `\\?\`: без этого файлы с путями длиннее 260 символов (MAX_PATH) роняли запуск.
Если распаковка всё же не удалась, launcher показывает диалог и пишет подробности в
`%TEMP%\vibe-netmap-launcher.log`. Сборка намеренно не включает `@capacitor/android`
(его Gradle-кэш давал пути в 267 символов) — Capacitor нужен только для Android.

Android-сборка требует JDK 21 и Android SDK (platform 36, build-tools 36.0.0); в CI это
настроено в `.github/workflows/build.yml` (Windows portable + zip, Linux AppImage, Android APK).

Экспорт JSON/CSV/PNG и импорт JSON в Electron идут через нативные диалоги (`ipcMain` +
`dialog.showSaveDialog`/`showOpenDialog`), а не через HTML-скачивание — так файл гарантированно
пишется на диск. В браузере остаются обычные blob-ссылки и `<input type=file>`.

На Android WebView не умеет скачивать blob-ссылки, поэтому экспорт пишет файл в кэш
приложения (`@capacitor/filesystem`) и открывает системный лист «Поделиться»
(`@capacitor/share`) — оттуда файл сохраняется в «Файлы», отправляется в мессенджер и т.п.
Импорт на Android работает через обычный выбор файла (SAF).

Если Node не установлен глобально, можно воспользоваться портативным `.tools/node`
(этот каталог локальный и в git не входит): `$env:Path = "$PWD\.tools\node;$env:Path"`,
затем вызывать `npm.cmd`/`npx.cmd`.

### Скриншот окна без ручного запуска

```powershell
$env:VIBE_CAPTURE = "$PWD\.tmp\desktop.png"
$env:VIBE_CAPTURE_EXIT = "1"
npx electron .
```

## Архитектура

```
src/
  core/         чистые функции без UI
    ip.ts       разбор/формат IPv4/IPv6, маски, классы, IANA, EUI-64, обратный DNS
    subnet.ts   блоки, разбиение, страницы хостов, свободное пространство
    history.ts  модель истории (сериализуемая, без побочных эффектов)
    project.ts  документ проекта, проверки, импорт/экспорт, поиск устройств
    ipPlan.ts   занятость блоков, свободные диапазоны, выдача адресов
  i18n/         словарь (ru) и t() с подстановками — готово к en
  app/          каркас, навигация, темы, адаптер хранилища, индекс проектов
  calc/         экран калькулятора и его панели
  projects/     список проектов, проект, устройства, план, проверки
  ui/           иконки, копирование, пагинация, модальные окна, форматирование
  canvas/       геометрия холста, отрисовка на Canvas 2D, редактор сцены
electron/
  main.cjs      окно, IPC, атомарная запись JSON
  preload.cjs   contextBridge: window.vibe
tests/          vitest: ip, subnet, history, project/plan, canvas
```

Принципы:

- **BigInt везде**, где есть адреса: IPv6 без потерь, IPv4 без переполнений. Никакой
  материализации огромных диапазонов — только страницы и формулы.
- **Чистое ядро**: `src/core` не знает про DOM, его легко переиспользовать в мобильной
  оболочке и покрывать тестами.
- **Одна модель данных** для будущих списка и холста: геометрия — необязательное поле.
- **Хранилище через интерфейс**: desktop — JSON-файлы через IPC, web/mobile — localStorage
  или файловый плагин Capacitor.

### Что нового в 0.4.2

- **Боковое меню.** Кнопка «Шаблоны» переехала в шапку к «Проектам» и «＋»; нижний ряд снова
  один «Калькулятор», ничего не обрезается.
- **Меню карточки проекта** больше не прячется под соседними карточками — открывается поверх.
- **Редактор рисунков на холсте.** Рамки, эллипсы, заметки и линии теперь можно:
  - перетаскивать целиком;
  - растягивать за 8 маркеров (у линий — за концы);
  - настраивать заливку и контур отдельно, включая «без заливки» и «без контура»;
  - менять толщину, пунктир, прозрачность и скругление;
  - у текста — размер и выравнивание.
  Панель свойств появляется при выборе рисунка. Поворот и группировка — в бэклоге.

### Версии

```powershell
npm run version:set -- 0.3.1
```

Скрипт `scripts/set-version.mjs` меняет версию в `package.json` и `android/app/build.gradle`
(`versionName` + вычисляемый `versionCode`). Имя артефактов подхватывается из версии:
`release/NetMapPlanner-<версия>-portable.exe`, `...-win.zip`, `...-debug.apk`.

Переименование в NetMap Planner: `build.productName` (имя exe/zip), UI-бренд, окно Electron,
`capacitor.config.ts` и Android `app_name`. Внутренние идентификаторы (`package.json` → `name`,
`appId`/`applicationId` `ru.vibe.netmap`, пути хранения) **не менялись** — иначе Android
поставил бы приложение как новое, а проекты «потерялись» бы в другом каталоге.

## Решения по спорным местам (зафиксировано)

- **Стек**: Electron + TypeScript + Preact, а не Tauri: один Chromium на Windows/Linux/Android,
  Canvas 2D ведёт себя одинаково, сборка без C++ тулчейна. Цена — размер установщика.
  Tauri выигрывал бы только в размере десктопной сборки, но на Linux использует WebKitGTK.
- **Хранение**: JSON-файлы (читаемость, экспорт одним файлом, отсутствие нативных модулей).
- **Слои**: у рисунков свой порядок и группы, но структурный слой устройств по умолчанию
  закреплён сверху (`pinnedTop`) — рисунок не может закрыть устройство, пока это не отключено.
- **Цвета проводов**: вычисляются из типа подключения (медь/оптика/радио/trunk/WAN/L3),
  ручной override разрешён; переключатель раскраски по среде/скорости/VLAN/статусу.
